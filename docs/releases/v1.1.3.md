## 本版改动

- `10cce14` Windows 版说明上传时改用 ASCII 文件名（否则 Release 里显示成 default.md）
- `a17bd5a` 修 CI 的 Generate release notes：脚本中文 print 在 cp1252 下抛异常
  - tools/release_note.py 开头把 stdout/stderr 重设为 utf-8（errors=replace）
  - Windows workflow 的失败日志上报移到 job 最后，任何一步挂了都能贴日志
  - 上一轮 Build EXE 已经能过（spec 的中文 print 已改 ASCII），失败点后移到生成说明这一步
- `c9f2095` 修 Windows CI 打包失败：spec 里的中文 print 在 cp1252 控制台抛 UnicodeEncodeError
  - Windows runner 上 Python 3.13 的默认 stdout 是 cp1252，print 中文直接抛UnicodeEncodeError，整个 PyInstaller 在加载 spec 阶段就挂掉
  - GuiZang.spec 的构建提示改成 ASCII；三个 workflow 的 Build 步骤加 PYTHONUTF8=1
  - 同时补上 shell: bash（之前 set/tee 那一步在默认 shell 下也没生效）
  - 根因来自 issue #1/#2 里贴出的 runner 日志
- `629d81d` Windows CI 的 Build 步骤补 shell: bash：默认 shell 下 set/tee 直接失败，pyinstaller 根本没跑
- `0706e71` Windows CI：失败时把 build.log 贴成 issue，便于定位（本地看不到 runner 日志）
- `3e1881e` CI 锁定 Qt 与 PyInstaller 版本，和本地验证过的组合对齐
  - 三个 workflow 统一装 PySide6-Essentials==6.12.0 + pyinstaller==6.22.3
  - 起因：Windows 构建在 v1.1.1/v1.1.2 连续失败，Linux 与 macOS 同一提交却成功，本地用同版本组合能正常打包，怀疑是 runner 上装到的新版本导致
  - 版本号不变，v1.1.2 tag 重新指向这次提交后重跑三平台
- `374002a` 版本 1.1.2：Linux 版可用 + 修复 CI 打包时的版本读取崩溃

## 使用说明

- 便携版：双击 `GuiZang-1.1.3-windows-x64.exe` 即用，资料库 `归藏.db` 就在 exe 同目录。
- 本目录是**该版本的归档**，里面的 `归藏.db` 是打包时的数据快照；日常使用请以最新版本目录为准。
- 覆盖升级：把旧目录里的 `归藏.db` 复制到新目录即可（或在软件里用「备份 / 恢复」搬运）。
